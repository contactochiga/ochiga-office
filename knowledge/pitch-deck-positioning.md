This file captures the current investor and enterprise positioning narrative for Ochiga and Oyi.

Title framing:
- Ochiga
- Infrastructure Operating Systems for Estates and Buildings
- Oyi is the operating layer for physical infrastructure

Core problem framing:
- modern estates and buildings run on fragmented systems
- access control is separate
- devices are disconnected
- maintenance is siloed
- payments and dues are isolated
- communication is scattered

Operator pain:
- no unified visibility
- no real-time control
- no operational intelligence

Resident pain:
- friction
- delays
- poor coordination

Approved reframing line:
Infrastructure today is not truly operated. It is managed in pieces.

Core solution framing:
Oyi is an infrastructure operating system that connects devices, users, operations, payments, and communication into a single operating layer.

Safe architectural framing:
Oyi is a multi-layer system with:
- operator layer
- consumer layer
- edge layer
- commercial layer
- intelligence layer

Strong but approved positioning lines:
- from fragmented tools to one coordinated system
- everything runs through one system
- full-stack infrastructure system
- infrastructure becomes programmable and responsive

Business model framing:
- deployment plus subscription
- setup or deployment fees
- monthly platform subscriptions
- tiered plans based on scale
- enterprise or custom integrations
- support and SLA packages

Market framing:
- real estate developers
- estate operators
- property management companies
- mixed-use developments
- institutional infrastructure projects

Competitive framing:
- full-stack system, not a point solution
- combines software, infrastructure, and operations
- AI embedded into the control layer
- edge and cloud architecture
- built for real deployment rather than only demos

Vision framing:
Ochiga is building the operating system for physical infrastructure, starting with estates and buildings and expanding toward districts and cities.
