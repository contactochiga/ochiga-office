# S7 final independent security certification: frozen protocol

**Evaluated runtime commit:** `fbac5ad1f90b2aa3a5ae867c1f7d2b3ca0098d9e` (branch `feature/settings-s1-s2`, local = remote, clean, verified before anything else). Evaluation only: no runtime code, migration, dependency or production configuration is modified; evidence commits add documents and the frozen test corpus only. No production account, credential, host or database is touched. This document is committed before the corpus is commissioned.

## 1. Security gates (all required for "certified")
G1 zero Critical findings · G2 zero unresolved High findings · G3 zero confirmed authentication bypasses · G4 zero unauthorized privilege escalations · G5 zero cross-account credential exposure · G6 zero replay or revocation bypasses **within the approved current-version contract** (the S7.0–S7.5.8 contracts as shipped; a documented mixed-version limitation is not a G6 failure but is reported) · G7 every test in the frozen corpus passes or its failure is adjudicated (below) · G8 the complete regression passes with true exit codes in the complete run · G9 no blocked or infrastructure-failed test is counted as passed.

## 2. Severity
**Critical:** authentication or authorization bypass, account takeover, credential or secret disclosure, privilege escalation. **High:** exploitable weakening of a protective control without a precondition outside the attacker's reach (throttling that does not throttle, replay of a single-use factor, a session that survives its revocation, a secret in a log). **Medium:** information disclosure that aids an attack (enumeration by response or timing), a control that fails open in a rare operational state, an auditability gap. **Low:** hardening gaps, misleading text, test-infrastructure faults. **Info:** documented limitations and observations. Each finding records evidence, reproduction, and whether it is in the shipped code or the test.

## 3. Independent corpus: commissioning and isolation ("first contact")
The corpus is written by **separate authors who start with no prior context** (four fresh agents, one per area, run in parallel). Their inputs are exactly: this document's gates and checklist (§4), the source tree **exported without git history** and **with every earlier test and certification artefact removed** (all `scripts/test-*.js`, `scripts/cert/`, `scripts/lib/`, `scripts/run-all-tests.js`, `scripts/measure-*`, and `docs/settings-domain/36…44*`, the evidence directories), the S7 design and contract documents `19…35` (the approved contract), an export of the previous release `52fd137` for mixed-version checks, and the machine facts (Chrome path, Docker images, port ranges). They are **not given**: the earlier certification protocol, report, corpus or manifest, any remediation contract or test, any earlier result or "answer". They must not read `/tmp/office-crm` or any path outside their export, working directory and the listed tools. Each author attests, in its delivery note, which paths it read. Expectations are derived from the gates and the contracts, **never from observed behaviour**: a check that fails against the system is reported as a candidate finding, and an author may not weaken it to make it pass; an author who believes a check is itself wrong keeps it and lists it as *disputed* with the reason.
Areas: **A** authentication, throttling, enumeration, sessions, logout, forwarding headers, API-key and edge-token restrictions, forged and legacy tokens, downgrade attempts (black-box over HTTP against real server processes); **B** MFA: TOTP, WebAuthn, recovery codes, factor management, step-up, administrator reset, break-glass, enforcement and grace, recovery abuse, cross-account and concurrency attacks; **C** database and multi-instance: migration order and dependencies, RLS and service-role boundaries, atomicity, replay protection and races under two servers on a disposable PostgREST stack, mixed-version behaviour (previous release against the same database), database failures, redaction; **D** browser: complete journeys at 1440, 1100, 900, 768 and 390 px with keyboard use, focus, touch targets, accessibility tree, expiry and error recovery, session termination, storage and network audits. Authors use their own TOTP, base32, CBOR and software authenticator code and black-box access (they start the real server as a process); they do not import earlier test helpers.

## 4. Checklist the authors must cover (generic requirements, no earlier results)
Password authentication; account enumeration (status, body, timing); login throttling (including that the correct password cannot bypass it, forwarding-header spoofing, concurrent bursts, multiple instances); API-key and edge-token restrictions on every human-account, session, MFA, step-up, reset and settings route; session issuance; session revocation (account-wide and individual); ordinary logout (a copied cookie must be refused; other sessions of the account must survive); password change and reset effects; account deactivation and restoration; deleted-and-recreated accounts; MFA challenges (no authority before completion); TOTP window and replay; WebAuthn (origin, relying party, signature, user verification, counter, challenge reuse); recovery codes (single use, other account, abuse, lock); factor management (enrolment, replacement, removal, last-factor guard, regeneration); step-up (purpose, expiry, session binding, permission loss, forged grants, no recovery codes); administrator recovery (reset, break-glass: off by default, once per id, password preserved, no HTTP route); enforcement policy and grace; legacy tokens; database failures (fail closed, honest errors, no detail); concurrency; cross-account attempts; forged tokens; expired challenges; permission removal; untrusted forwarding headers; multi-instance and mixed-version behaviour; authentication downgrade attempts; secrets and identifiers never in responses, logs, audit or storage.

## 5. Freeze, execution, adjudication
1. Authors deliver to a staging area outside the repository. The coordinator checks only structure (runs, exit codes, no import of earlier helpers) and does **not edit expectations**.
2. The corpus is copied unchanged to `scripts/final-cert/<area>/`, SHA-256 digests are recorded in `46_S7_FINAL_CERTIFICATION_CORPUS_MANIFEST.md`, and both are committed and pushed **before the official run**.
3. The official run executes the frozen corpus in a **clean checkout** of that commit (`npm ci`, runtime files identical to the evaluated commit, verified by an empty diff), then the complete regression with the corrected runner and true exit codes: gates, the frozen S7.5.9 corpus (`--cert`), every Office suite (S7.0–S7.5.8, R1–R4, Team permissions, WhatsApp autonomy, Settings S1–S6, browser suites), every Postgres suite, `npm audit`.
4. A failing check is a finding unless adjudicated as a **test defect**: only when the check contradicts the written contract or is demonstrably malformed; the adjudication, the reason and the evidence are recorded in the report; a check is never removed or relaxed to obtain a pass; a re-run of an adjudicated test is recorded separately and the original failure stays in the record. A test that cannot run (infrastructure) is **blocked**, reported as blocked, and counts against G9 until it runs.
5. The decision applies §1 to the recorded results. Production-owner items (API-key fallback dependency, historical audit rows, WebAuthn domain, key custody and backup, applied migrations, fleet inventory, recovery rehearsal, backup/restore drill) are listed as not verifiable here and are never marked passed.
